## 2026-11-25 — M0 실기 진행 (Mac, ESP-IDF v5.5.5)

**바뀐 파일**
- ESP-IDF v5.5.5를 `~/esp/esp-idf`에 설치(ESP32-P4 v3.2 대응). `sdkconfig.defaults`를 16MB 플래시,
  32MB PSRAM 200MHz, `ESP32P4_SELECTS_REV_LESS_V3=n`, LVGL 설정으로 교체. `partitions.csv` 추가(앱 6MB, 저장소 9MB).
- `components/board/`: 보드 초기화(D-PHY LDO → DSI → JD9365 → LVGL 포트, GSL3680 터치, 백라이트 PWM).
  핀·DSI 속도·회전·터치 미러는 모두 Kconfig 항목(기본값은 제조사 자료 값).
- `components/esp_lcd_jd9365/`, `components/esp_lcd_touch_gsl3680/`: 제조사 데모에서 가져옴. 출처·라이선스는
  `components/THIRD_PARTY.md`(gsl_point_id.c는 GPL-2.0+ 표기 → 배포 시 검토 필요).
- 터치 드라이버 수정: 24바이트 스택 버퍼에 44바이트를 읽던 오버플로, 손가락 수 상한 미검사, 잘못된 "failed" 로그.
- `main/main.c`: M0 화면(제목, 네 구석 표시, 터치 좌표 라벨, 터치 위치 빨간 점, 터치 좌표 시리얼 로그).
- 의존성: LVGL 9.4.0, esp_lvgl_port 2.9.0(LVGL ≥9.3 필요), esp_lcd_touch 1.2.1.

**확인한 내용**
- `idf.py build` 통과(프로젝트 코드 경고 없음).
- 플래시 전 16MB 전체 백업: `backup/factory_flash_16MB.bin`(Git 제외), SHA-256은 `backup/SHA256SUMS`,
  칩과 `verify_flash` 일치 확인. 이후 이 백업으로 기본 펌웨어 복원도 성공.
- 부팅: PSRAM 32MB @200MHz, 칩 v3.2, 플래시 16MB(Boya) 확인.
- `MIPI_DSI_PHY_CLK_SRC_DEFAULT`(PLL_F20M)는 v3.x에서 abort → `phy_clk_src = 0`으로 수정.
- 패널 명령 경로 정상(LCD ID `93 65 04`), GSL3680 펌웨어 로드 정상, **터치 좌표 로그 확인**.
- **화면 영상은 실패**: 회전 없음, DSI 하드웨어 패턴, 프레임버퍼 직접 쓰기, 1500/1000 Mbps 모두에서
  회색 가로줄만 보임. 클럭 레인 HS 고정은 DSI 버스 초기화에서 멈춤.
- 기본 펌웨어(ESP-IDF v6.0.2, JD9365 드라이버 2.0.2) 복원 시 **화면은 나오지만 가로줄이 함께 보인다**고 사용자 확인.

**남은 문제**
- 기본 펌웨어에서도 줄이 보이므로 디스플레이 FPC 케이블 접촉/손상 등 하드웨어 문제 가능성이 높음.
  케이블 재장착 후 기본 펌웨어로 줄이 사라지는지 먼저 확인.
- 하드웨어가 정상이 되면 M0 펌웨어 재시험. 그래도 영상이 안 나오면 기본 펌웨어와 같은 ESP-IDF v6.0.2로 이전 검토.
- 현재 보드에는 **기본 펌웨어**가 들어 있음. M0 바이너리는 `idf.py -p /dev/cu.usbmodem83201 flash`로 다시 올림.
- 자가진단(`BOARD_DISPLAY_SELFTEST`)은 기본 켜짐 — 화면 확인 후 끌 것.
- M0 미완료: 가로 1280×800 글자 표시 미확인.
- 2026-11-25 추가: 디스플레이 FPC 케이블을 재장착한 뒤에도 기본 펌웨어에서 가로줄이 계속 보임(사용자 확인).
  패널·케이블·보드 커넥터 중 하드웨어 불량 가능성이 높음 → 판매처 문의/교환 검토.
  다만 기본 펌웨어는 줄과 함께 영상이 나오고 M0 펌웨어는 영상이 전혀 안 나오므로 소프트웨어 차이도 남아 있음.

## 2026-11-25 — M1 오디오 입력 ✅

**바뀐 파일**
- `components/level_meter/`: 순수 C. 20Hz 1차 DC 차단 필터 → 10ms 블록 RMS/피크 → dBFS.
  dBFS는 AES17 기준(풀스케일 사인 = 0 dBFS). 무음은 −120 dBFS로 고정.
- `components/audio_in/`: ES8311(esp_codec_dev 1.6.2, I2C 0x18) + I2S1 마스터(MCLK 13/BCLK 12/WS 10/DIN 11),
  48kHz 16bit 스테레오 수신 후 마이크 슬롯만 사용. 12초 링 버퍼(1.1MB, PSRAM), `audio_task`는 코어 1·높은 우선순위.
  `audio_ring.c`는 순수 C. 핀·샘플레이트·게인(24dB)·마이크 슬롯·링 길이는 Kconfig(*Audio input*).
- `test/`: 호스트 단위 테스트(`make -C test`) — 레벨 계산(0/−18 dBFS 사인, DC 제거, 20Hz 코너, 무음)과 링 버퍼(랩어라운드, 초과 쓰기).
- `main/main.c`: 0.2초마다 `mic rms / peak / 막대 / 다른 슬롯 / 블록 수 / 오류` 시리얼 출력.
  디버그 옵션 `MUSIC_DISPLAY_PCM_DUMP`(기본 끔): 10초마다 1초 원시 PCM을 16진수로 출력.
- `components/board/`: 백라이트 PWM 주파수를 Kconfig(`BOARD_BACKLIGHT_PWM_HZ`, 기본 50kHz)로 분리.
  디스플레이 자가진단은 기본 끔.

**확인한 내용**
- `idf.py build` 통과, 호스트 테스트 통과.
- 실기: 블록 100개/초, 읽기 오류 0. 마이크는 **왼쪽 슬롯**(오른쪽은 0).
- 조용할 때 약 −62 dBFS, 박수·말소리 −20 ~ −25 dBFS로 반응 → **M1 완료 기준 충족**.
- 제조사 값(20kHz) 백라이트 PWM이 마이크 입력에 −47 dBFS 20kHz 톤으로 섞이는 것을 원시 PCM 분석으로 확인.
  50kHz로 올린 뒤 80% 밝기에서도 바닥 잡음이 −62 dBFS로 PWM 없는 상태와 같아짐.

**남은 문제**
- 50kHz PWM에서 백라이트 밝기 조절이 정상인지는 화면 하드웨어 문제로 육안 확인 못 함.
- 0VU 기준(`vu_ref_dbfs`, 기본 −18) NVS 저장은 설정 화면(M4/M7)에서 구현.
- 마이크 게인 24dB에서 음악 재생 시 클리핑 여부는 M2에서 실제 음악으로 확인.
- 화면 영상 문제(M0)는 그대로 — 판매처 문의 또는 ESP-IDF v6.0.2 이전 검토.

- `components/board`: DPI 설정을 직접 정의(`in_color_format`, `BOARD_DPI_CLOCK_MHZ` 기본 60),
  IDF 6에서는 `esp_lcd_dpi_panel_enable_dma2d()` 호출, 패널 행/열 반전 옵션(`BOARD_PANEL_FLIP_ROWS` 기본 켬, `_COLS`).

- `main/CMakeLists.txt`: IDF 6 GCC의 LVGL `-Wattributes` 경고를 LVGL에만 해제.
- `AGENTS.md`: 다른 코딩 에이전트(Codex)용 인수인계 문서.

**확인한 내용**

- 출하 펌웨어 분석: 패널 명령표가 데모 표와 값이 다름(예: 0x01=0x44/0x39, 0x04=0x38/0x41, 0x18=0xAF/0xD7).
- **factory 표 적용 후 화면에 글자가 나옴**(가로줄은 제조사 펌웨어처럼 남아 있음). 마이크·터치도 IDF 6에서 정상.
- 화면이 좌우 거울상(TOP-LEFT가 오른쪽 위), 터치 점이 손가락과 다른 위치 → 행 반전(GS) 켠 빌드를 올렸으나 **결과 미확인**.

**남은 문제**
- 화면 방향 확인 → 터치 축 정렬(네 구석 터치 로그로) → M0 완료.
- 가로줄(하드웨어 의심). DPI 80MHz/레인 1000Mbps로 개선되는지 시험해 볼 수 있음.

## 2026-11-25 — 사진 판독에 따른 M0 반전 시험 및 M2 준비

**바뀐 파일**
- `sdkconfig.idf6`: 사용자 사진 `IMG_9536.HEIC`에서 좌우 거울상(왼쪽 위에 뒤집힌 TOP-RIGHT)을 확인.

  omega=13.6, zeta=0.815로 99% 도달 약 300ms, 오버슈트 약 1.2%. 입력은 dB 비율이 아닌 선형 진폭.
- `components/ui/`: 크기를 받는 독립 아날로그 미터(CLASSIC_CREAM) 위젯.
  RGB565 눈금판/따뜻한 방사형 배경을 PSRAM에 캐시하고 바늘은 별도 LVGL 선으로 갱신.
- `main/main.c`, `main/Kconfig.projbuild`, `main/CMakeLists.txt`: `MUSIC_DISPLAY_DIAGNOSTICS` 옵션 추가(기본 켬).
  끄면 16ms 타이머로 모노 마이크 값을 두 미터에 동일하게 표시하는 M2 미리보기.
  현재 보드에는 계속 M0 진단 화면이 표시됨. M0 검증 전에 M2 완료를 선언하지 않음.
- `test/`: 30/60/1000Hz 스텝 응답, 상승 시간/오버슈트/복귀, 프레임 간격 변화, 잘못된 입력 테스트 추가.

**확인한 내용**
- ESP-IDF 6.0.2 전체 빌드 및 `/dev/cu.usbmodem83201` 업로드 통과, 기록 데이터 해시 검증 통과.

  오디오 블록 약 100개/초, 읽기 오류 0. 화면 방향 자체는 시리얼로 확인할 수 없음.
- 일반 호스트 테스트 및 AddressSanitizer/UndefinedBehaviorSanitizer 테스트 통과.
- 아날로그 위젯은 전체 빌드에 포함해 컴파일됨. 비활성 M2 앱 분기도 같은 IDF 컴파일 옵션으로 별도 컴파일 통과.

**남은 문제**
- 반전 설정 변경 후 새 사진 필요. 정상 글자/네 구석 배치 확인 뒤 네 구석 터치 로그 수집 필요.
- 사진에서 가로줄은 계속 관찰됨. 제조사 펌웨어에서도 나타난 이력과 함께 하드웨어 가능성은 있으나 원인 확정 아님.
