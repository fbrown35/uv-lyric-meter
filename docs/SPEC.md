# ESP32-P4 Music Display — VU 미터 + 곡 인식 + 가사

> 이 문서는 Claude Code에게 주는 프로젝트 사양서다. 작업은 아래 **마일스톤 순서대로** 진행하고, 마일스톤마다 `idf.py build`가 통과하고 완료 기준을 충족하는지 확인한 뒤 다음으로 넘어간다.

---

## 1. 개요

10.1인치 ESP32-P4 터치 디스플레이에 마이크로 들어온 음악을 실시간으로 보여주는 장치를 만든다.

- 마이크 입력 → **VU 미터**(아날로그 바늘형 / 디지털 LED형)
- 주기적으로 녹음 → **AudD API**로 곡 인식 → 곡 정보(제목, 아티스트, 앨범, 앨범 아트)
- **LRCLIB API**로 시간 정보가 붙은 가사를 받아 재생 위치에 맞춰 표시
- 사용자가 **화면 구성 4종**과 **미터 스타일**을 터치로 선택하고, 선택값은 재부팅 후에도 유지

## 3. 개발 환경

- **ESP-IDF v5.4 이상** (ESP32-P4 정식 지원 버전)
- **LVGL v9.x** + `esp_lvgl_port`
- 보드 BSP 컴포넌트(제조사 제공 또는 `esp-bsp`)
- 컴포넌트는 `idf_component.yml`로 관리
- 언어: C (필요하면 C++), 코드 주석은 영어, 화면에 나오는 문구는 한국어

## 4. 화면 방향과 렌더링

- 패널은 기본이 800×1280 세로형이다. UI는 **1280×800 가로 화면**을 기준으로 설계한다.
- 회전은 LVGL 디스플레이 회전 또는 PPA(픽셀 처리 가속기)로 처리하고, 두 방식의 프레임 속도를 재서 빠른 쪽을 쓴다.
- 프레임 버퍼는 PSRAM에 두고, 가능하면 더블 버퍼를 쓴다.
- 목표 프레임 속도: VU 미터 **30fps 이상**(목표 60fps). 바늘이나 막대가 있는 영역만 다시 그린다.

## 5. 화면 구성 (Screen Mode)

```c
typedef enum {
    SCREEN_FULL,         // VU 미터 + 곡 정보 + 가사 1~2줄
    SCREEN_VU_ONLY,      // VU 미터만 크게
    SCREEN_INFO_LYRICS,  // 곡 정보 + 가사 (미터 없음)
    SCREEN_LYRICS_FOCUS, // 가사 위주
} screen_mode_t;
```

### 5.1 SCREEN_FULL
```
┌──────────────────────────────────────────────┐
│   [ L 미터 ]              [ R 미터 ]         │  위쪽 약 55%
├──────────┬───────────────────────────────────┤
│ 앨범 아트 │ 제목 (큰 글씨)                     │
│ 200×200  │ 아티스트 · 앨범                     │  아래쪽 약 45%
│          │ ▶ 현재 가사 줄 (강조)               │
│          │   다음 가사 줄 (흐리게)              │
└──────────┴───────────────────────────────────┘
```

### 5.2 SCREEN_VU_ONLY
- 미터 두 개가 화면을 가득 채운다(L/R 좌우 배치).
- 디지털 스타일일 때는 가로 막대 두 줄을 크게 표시한다.
- 아래쪽에 곡 제목 한 줄을 작게 띄우는 옵션을 둔다(설정에서 켜고 끔, 기본값 끔).

### 5.3 SCREEN_INFO_LYRICS
- 왼쪽: 큰 앨범 아트(약 400×400), 제목, 아티스트, 앨범, 발매 연도
- 오른쪽: 가사 5~7줄. 현재 줄은 강조하고 자동으로 스크롤한다.

### 5.4 SCREEN_LYRICS_FOCUS
- 배경: 앨범 아트를 흐리게 하거나 대표 색으로 만든 그라데이션
- 가운데 현재 가사 줄을 아주 크게(48px 이상) 표시하고, 위아래로 이전/다음 줄을 흐리게 표시
- 줄이 바뀔 때 부드럽게 위로 밀려 올라가는 애니메이션(200~300ms)
- 맨 아래 작게: 제목 · 아티스트
- 시간 정보가 없는 가사(plain)뿐이면 전체 가사를 천천히 자동 스크롤

### 5.5 공통 상태 표시
- 곡 정보가 없을 때: "음악을 듣는 중…" 같은 대기 화면
- 인식 실패: "곡을 찾지 못했어요" 표시 후 다음 주기에 다시 시도
- 가사 없음: 곡 정보만 표시하고 가사 영역에 "가사 정보 없음"
- 상단 구석에 작은 아이콘: Wi-Fi 상태, 인식 진행 중 표시

## 6. VU 미터 스타일

```c
typedef enum { METER_ANALOG, METER_DIGITAL } meter_style_t;
```

### 6.1 아날로그 (바늘형)
- 구성: 배경 이미지(눈금판) + 바늘 + 빨간 과부하 구간 + 피크 표시등
- 눈금: VU 기준 −20, −10, −7, −5, −3, −2, −1, 0, +1, +2, +3, 아래쪽 0~100% 보조 눈금
- **색상 테마 (여러 색):**

```c
typedef enum {
    ANALOG_THEME_CLASSIC_CREAM, // 크림색 바탕, 검은 눈금, 빨간 과부하 구간, 따뜻한 백라이트
    ANALOG_THEME_AMBER,         // 호박색 백라이트
    ANALOG_THEME_BLACK,         // 검은 바탕, 흰 눈금
    ANALOG_THEME_BLUE,          // 푸른 백라이트(빈티지 앰프 느낌)
    ANALOG_THEME_GREEN,         // 녹색 형광 느낌
} analog_theme_t;
```

- 테마별 눈금판은 **코드(LVGL 드로잉)로 생성**해 PSRAM에 캐시한다. 이미지 에셋을 따로 만들지 않아도 되고 테마를 쉽게 추가할 수 있다.
- 바늘은 매 프레임 각도를 계산해서 안티에일리어싱된 선(또는 회전한 바늘 이미지)으로 그린다.
- 백라이트 효과: 눈금판 가운데를 밝게 하는 방사형 그라데이션
- **디자인 원칙:** 특정 회사 제품(예: Waves 플러그인)의 로고, 상표, 문구, 고유한 디자인을 그대로 베끼지 않는다. 고전 VU 미터의 일반적인 형태만 참고한 독자 디자인으로 만든다.

### 6.2 디지털 (LED형)
- L/R 각각 세그먼트 막대(가로형 기본, 세로형 옵션)
- 세그먼트 약 30~40개. 색상 구간: 초록(−∞~−6dB) → 노랑(−6~0dB) → 빨강(0dB 이상)
- **피크 홀드:** 최고점 세그먼트를 1.5초간 유지한 뒤 천천히 떨어뜨림
- 막대 옆 또는 아래에 dB 숫자 표시(옵션)
- 색상 테마: 기본(초록·노랑·빨강), 단색 청록, 단색 호박색

### 6.3 스테레오 처리
- 마이크가 하나(모노)면 L/R에 같은 값을 쓰되, 미세한 차이를 넣는 "의사 스테레오" 옵션을 둔다(기본값 끔).
- 스테레오 마이크 입력이 가능하면 실제 L/R를 쓴다.

## 7. 오디오 처리

### 7.1 입력
- I2S 입력: 44.1kHz 또는 48kHz, 16bit(또는 32bit 슬롯), 모노 또는 스테레오
- DMA → 링 버퍼(PSRAM, 약 12초 분량) — 곡 인식용 녹음도 이 버퍼에서 꺼내 쓴다

### 7.2 레벨 계산
- 10ms 블록마다 RMS 계산 → dBFS로 변환
- 보정값 `vu_ref_dbfs`(기본값 −18dBFS = 0VU)는 설정에서 조절할 수 있게 하고 NVS에 저장
- 직류 성분 제거용 고역 통과 필터(약 20Hz) 적용

### 7.3 바늘 움직임 (아날로그)
- 표준 VU 특성: 0VU에 해당하는 신호를 넣으면 **약 300ms 만에 99%까지 올라가고, 1~1.5% 정도 살짝 넘쳤다가** 제자리로 돌아온다.
- 2차 스프링-감쇠 모델로 구현:
  ```
  accel = k * (target - pos) - c * vel
  vel  += accel * dt
  pos  += vel * dt
  ```
  위 조건에 맞게 `k`, `c` 값을 조정하고, 파라미터는 헤더 파일 상수로 뺀다.
- 바늘 위치는 오디오 블록 단위가 아니라 **렌더링 프레임마다** 계산해서 부드럽게 움직이게 한다.

### 7.4 디지털 미터 움직임
- 피크 미터 방식: 빠르게 올라가고(약 5ms), 천천히 내려감(약 20dB/초)
- 피크 홀드는 6.2 참고

## 8. 곡 인식 (AudD)

- 엔드포인트: `POST https://api.audd.io/` (multipart: `api_token`, `file`, `return=apple_music,spotify`)
- 녹음: 링 버퍼에서 **8초** 분량을 꺼내 16kHz 모노 16bit WAV로 변환(다운샘플링) 후 전송
- **인식 요청 시점:**
  1. 무음 상태가 3초 이상 이어지다가 음악이 시작될 때
  2. 마지막 인식 후 90초가 지났을 때(설정 가능)
  3. 곡이 끝날 것으로 예상되는 시점 직후(곡 길이와 재생 위치로 계산)
  4. 화면 길게 누르기 → 수동 인식
- 같은 곡이 다시 인식되면 화면을 바꾸지 않고 재생 위치만 다시 맞춘다.
- 무음일 때는 요청하지 않는다(무료 사용량 절약).
- 응답에서 쓸 필드: `artist`, `title`, `album`, `release_date`, `timecode`, 앨범 아트 URL(`apple_music` 쪽 artwork 값). **실제 응답 구조는 AudD 문서로 확인한 뒤 구현한다.**
- 앨범 아트: JPEG를 받아서 P4의 하드웨어 JPEG 디코더로 풀고, 화면 크기에 맞게 줄여 PSRAM에 캐시
- **API 토큰은 코드에 직접 쓰지 않는다.** menuconfig 기본값 → NVS에 저장 → 설정 화면에서 바꿀 수 있게 한다. `sdkconfig`에 실제 토큰이 들어가지 않도록 `.gitignore`를 관리한다.

## 9. 가사 (LRCLIB)

- 1순위: `GET https://lrclib.net/api/get?artist_name=…&track_name=…&album_name=…&duration=…`
  - `syncedLyrics`(LRC 형식, `[mm:ss.xx] 가사`)가 있으면 사용
  - 없으면 `plainLyrics` 사용
- 찾지 못하면 `/api/search?q=아티스트 제목`으로 한 번 더 시도
- 2순위(대안): AudD 가사 기능
- 요청 시 `User-Agent` 헤더에 앱 이름과 버전을 넣는다.
- **재생 위치 계산:**
  ```
  현재 위치 = AudD timecode + (지금 시각 − 녹음 시작 시각)
  ```
  설정에서 ±0.1초 단위로 가사 싱크를 조절할 수 있게 한다.
- LRC 파서: 한 줄에 시간 태그가 여러 개 있는 경우, 메타데이터 태그(`[ar:]`, `[ti:]`, `[offset:]`) 처리
- 받은 가사는 최근 20곡까지 메모리(또는 플래시)에 캐시

## 10. 폰트

- 한국어, 영어, 숫자가 필수이고 일본어 가나는 있으면 좋음
- **방법 A (권장):** LVGL **TinyTTF**로 TTF 파일을 플래시에서 읽어 실행 중에 글자를 그림 → 모든 글자 지원, 크기 자유
- **방법 B:** `lv_font_conv`로 한글 완성형 2,350자 + 영문을 비트맵 폰트로 변환(크기별로 따로)
- 먼저 방법 A로 성능(가사 애니메이션 프레임 속도)을 재보고, 부족하면 자주 쓰는 크기만 B로 바꾼다.
- 폰트는 Noto Sans KR, Pretendard 등 **OFL 라이선스** 폰트를 쓰고, 라이선스 파일을 저장소에 함께 넣는다.

## 11. 조작 방법 (터치)

| 동작 | 기능 |
|---|---|
| 좌우로 밀기 | 화면 구성 바꾸기 (FULL → VU_ONLY → INFO_LYRICS → LYRICS_FOCUS → 처음으로) |
| 미터 영역 두 번 탭 | 아날로그 ↔ 디지털 전환 |
| 미터 영역 위아래로 밀기 | 색상 테마 바꾸기 |
| 화면 길게 누르기(1초) | 지금 곡 인식 |
| 오른쪽 위 구석 탭 | 설정 화면 열기 |

- 화면이 바뀔 때 0.2초 정도 서서히 바뀌는 효과를 주고, 바뀐 모드 이름을 1초간 작게 표시한다.

### 설정 화면
- 화면 구성 / 미터 스타일 / 아날로그 테마 / 디지털 테마 (선택 목록)
- 0VU 기준 레벨, 가사 싱크 조절
- 자동 인식 간격, 자동 인식 켜기/끄기
- 화면 밝기, 야간 자동 어둡게 하기(옵션)
- Wi-Fi 설정, AudD API 토큰 입력
- 모든 설정은 **NVS에 저장**하고 부팅할 때 불러온다.

## 12. 소프트웨어 구조

### 12.1 태스크

| 태스크 | 코어 | 우선순위 | 하는 일 |
|---|---|---|---|
| `audio_task` | 1 | 높음 | I2S 읽기, 링 버퍼 쓰기, RMS/dB 계산 |
| `lvgl_task` | 0 | 중간 | UI 렌더링, 바늘 움직임 계산 |
| `recog_task` | 0 | 낮음 | 녹음 꺼내기 → WAV 변환 → AudD 요청 → 응답 처리 |
| `lyrics_task` | 0 | 낮음 | LRCLIB 요청, 가사 파싱 |
| `net_task` | - | - | Wi-Fi 연결, 시간 동기화(SNTP) |

- 태스크끼리는 FreeRTOS 큐나 이벤트 그룹으로 통신한다. LVGL 객체는 **lvgl_task 안에서만** 건드린다(`lvgl_port_lock` 사용).
- HTTPS는 `esp_http_client` + `esp_crt_bundle`로 처리한다.

### 12.2 디렉터리 구조 (제안)

```
music-display/
├── main/
│   ├── main.c
│   ├── app_state.c/.h        # 현재 모드, 곡 정보, 설정 (공유 상태)
│   ├── settings.c/.h         # NVS 저장/불러오기
│   └── Kconfig.projbuild     # 핀, API 토큰 기본값 등
├── components/
│   ├── audio_in/             # I2S, 링 버퍼, 다운샘플링
│   ├── level_meter/          # RMS, dB, 바늘 움직임, 피크 홀드
│   ├── recognizer/           # AudD 클라이언트, WAV 인코더
│   ├── lyrics/               # LRCLIB 클라이언트, LRC 파서
│   ├── ui/
│   │   ├── ui_manager.c      # 화면 전환, 제스처
│   │   ├── screens/          # full / vu_only / info_lyrics / lyrics_focus / settings
│   │   └── widgets/          # analog_meter, digital_meter, lyrics_view, album_art
│   └── net/                  # Wi-Fi, SNTP
├── assets/fonts/
├── test/                     # 호스트(PC)에서 돌리는 단위 테스트
└── idf_component.yml
```

- **미터 위젯은 화면과 분리한다.** `analog_meter_create(parent, w, h, theme)`처럼 크기를 받아서 만들고, 각 화면이 위젯을 원하는 크기로 배치한다.
- 오디오 처리, LRC 파서, WAV 인코더는 하드웨어 없이 PC에서 테스트할 수 있게 순수 C로 짠다.

## 13. 마일스톤

| # | 내용 | 완료 기준 |
|---|---|---|
| M0 | 보드 확인, BSP로 화면 띄우기 | 1280×800 가로 화면에 글자 표시, 터치 좌표 로그 출력 |

## 14. 작업 규칙 (Claude Code용)

- 모르는 하드웨어 정보(핀 번호, 코덱 종류)는 추측해서 코드에 넣지 말고 Kconfig 항목으로 빼고 TODO 주석을 남긴다.
- API 토큰, Wi-Fi 비밀번호를 커밋하지 않는다.
- 새 기능을 넣을 때마다 `idf.py build`로 빌드가 되는지 확인한다.
- 메모리: 큰 버퍼(프레임 버퍼, 링 버퍼, 앨범 아트, 폰트 캐시)는 PSRAM에, 실시간 오디오 처리용 작은 버퍼는 내부 RAM에 둔다.
- 외부 API 응답 구조는 공식 문서로 확인하고, 응답 파싱이 실패해도 앱이 죽지 않게 한다.
- 가사는 개인용 표시 목적이다. 상품화할 경우 가사 표시는 저작권 라이선스 검토가 필요하다는 점을 README에 적어 둔다.
